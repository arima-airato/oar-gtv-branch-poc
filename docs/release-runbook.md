# リリース手順（運用ルール 5節）

## 手順

1. `develop` への新規マージを止める（機能凍結）
2. 検証を通す
3. タグを打つ

```
git tag -a oar/v1.2.0 -m "承認番号 xxx / 軽微変更届 yyy"
git push origin oar/v1.2.0
```

タグを push すると `release-evidence` ワークフローが動き、出荷5点セットが
Artifact として保存されます。

## リリース前チェックリスト

- [ ] develop への新規マージを止めた（機能凍結）
- [ ] 自動テストが全て通っている
- [ ] 品目別の差分を出し、変更点一覧を作った（`tools/product_diff.py`）
- [ ] Core を触った変更について、両品目の影響評価が済んでいる
- [ ] 変更区分（一変／軽微変更／届出不要）の判断が記録されている
- [ ] リスク管理表の更新が必要なら済んでいる
- [ ] 実行ファイルの中身の一覧（SBOM）を出力した
- [ ] 他品目のコードが混入していないことを確認した（`build/verify_isolation.py`）
- [ ] タグを打ち、上記一式をタグに紐づけて保管した

## 出荷時に一緒に残す5点

| | 中身 | このリポジトリでの出どころ |
| --- | --- | --- |
| 1 | 実行ファイル | `build/<品目>.spec` の output |
| 2 | 由来 | タグとコミット番号 |
| 3 | 部品表（SBOM） | `build/collect_manifest.py` ＋ 外部部品の版 |
| 4 | テスト結果 | `tests` ワークフローのログ |
| 5 | 前回からの差分 | `tools/product_diff.py` の出力 |

`tools/release_evidence.py` がこの5点を1つの JSON にまとめます。

## タグの注意

Git は `oar` というタグと `oar/…` を同時に持てません。区切りは最初から統一します。

```
git tag -l 'oar/*'    # 品目別に一覧
```
